# 产品巡游

这份巡游面向第一次打开仓库的人。目标不是枚举按钮，而是说明一次可信问答如何从资料进入、经过检索、落到引用，再成为可回归的质量样本。

![多模态 RAG 主视觉](assets/multimodal-rag-hero.png)

## 先认识一个画布和两个抽屉

默认页面以问答为中心，工程信息按需出现：

| 区域 | 默认可见 | 解决的问题 | 常见动作 |
| --- | :---: | --- | --- |
| 问答画布 | ✓ | “针对这些资料，答案是什么？” | 输入问题、查看回答与来源、提交反馈 |
| 资料库抽屉 |  | “系统现在知道什么？” | 上传、URL 导入、选择资料、重建或删除 |
| 检索调试抽屉 |  | “系统为什么这样回答？” | 查看 Trace、引用上下文、图谱、质量与评测 |

简洁（普通）模式不会展示 Provider、候选池、权重、原始检索分值和系统指标。需要实验时切换“调试”，检索参数才在 Composer 上方展开；点击“资料库”或“检索调试”打开相应抽屉，`Esc` 关闭并把焦点交还给原触发位置。

![Question-first 问答首页](screenshots/01-workbench-beta.png)

项目首页只展示当前 Question-first 界面；历史截图仅保留在截图验证索引中，用于回归和信息层级演进的审查。

## 一次完整任务

### 1. 导入资料

从顶栏“资料库”打开抽屉，可以上传 PDF、DOCX、Markdown、纯文本、PNG 或 JPEG，也可以导入公开 HTTP(S) URL。导入会先进入可恢复任务：

1. 校验文件名、扩展名、大小、空内容、PDF/图片签名与 DOCX Office ZIP 边界。
2. URL 导入校验 scheme、嵌入凭据、DNS、重定向、最终地址、内容类型和响应大小。
3. 用 KB、内容、chunker/embedding/index version 建立幂等 job。
4. 本地 worker 领取任务，解析文本/DOCX；图片在可选 Tesseract 环境下 OCR。
5. 分块、嵌入、写入、质量分析；阶段间支持取消，失败最多自动尝试三次。
6. 将文档写入 SQLite，将 chunk 写入 BM25 与当前 vector store。

文档卡片会显示索引状态、chunk 数量、字符数与质量摘要。失败时会保留明确原因和重试入口；未成功的临时上传文件会清理。

### 2. 选择检索范围

先选择知识库，再可选具体文档。请求先按 `knowledge_base_ids` 隔离，再应用 `document_ids`。这仍是本地资料范围，不应被误解为多租户授权；真正的 workspace 边界见[生产适配方案](production-adapters.md)。

### 3. 提问

简洁模式只暴露必要选项，适合日常问答。会话与消息保存在 SQLite，回答通过 SSE 增量显示；完成前标为“待审计”，最终事件才发布引用与可信度。提交后可以停止；超时、429 或 Provider 不可用时显示可读原因、请求 ID 与重试。

回答有两种合法结果：

- **有足够证据**：输出受证据约束的答案、置信度、引用和引用审计。
- **证据不足**：明确拒答并给出资料缺口，不用低相关向量片段拼凑结论。

### 4. 阅读引用，而不只读答案

每条引用都保留文档、chunk、页码、标题路径、snippet 和分数组成。简洁模式只展示来源摘要；切换调试模式才显示原始检索分值。点击引用可以加载相邻 chunk，从短片段回到上下文，避免断章取义。下图展示仅检索模式的完成态来源列表；回答模式的引用点击后复用同一证据抽屉查看原文与相邻上下文。

![FastAPI 反向代理问题的仅检索结果与五条相关来源](screenshots/16-question-first-sources.png)

### 5. 在检索调试抽屉中定位原因

点击顶栏“检索调试”打开抽屉。Trace 不是原始 JSON dump，而是十个语义阶段与一张 Evidence Chain：query enrichment、BM25、向量召回、RRF、Graph、parent expansion、MMR、rerank、回答/拒答决策、引用审计。它回答这些调试问题：

- 是关键词没有命中，还是语义召回没有覆盖？
- 候选在哪一步被去重或降序？
- MMR 是否减少重复，同时损失了关键证据？
- 拒答来自零候选、分数不足，还是只命中通用噪声？
- 回答中有多少主张被真实引用覆盖？

更完整的阶段说明见[检索与可信回答](retrieval-explained.md)。

### 6. 用调试（专家）模式做对照实验

顶栏“调试”模式保留普通问答能力，并按需增加：

| 控件 | 作用 | 常见诊断方式 |
| --- | --- | --- |
| Search mode | hybrid / keyword / semantic | 比较词法与语义分支贡献 |
| Profile | balanced / precision / recall | 先选择目标，再微调参数 |
| Top K | 最终证据条数 | 控制回答上下文体积 |
| Candidate K | 初始候选池 | 检查召回上限是否过小 |
| BM25 / Vector weight | 融合比例 | 专有名词与语义问题分别试验 |
| MMR λ | 相关性与多样性权衡 | 降低重复片段或保留高相似证据 |
| Min score | 最低证据门槛 | 调整误答与过度拒答的平衡 |
| Query rewrite / Rerank | 可选阶段 | 定位扩展查询或重排带来的影响 |

参数都有范围约束，执行中会禁用冲突操作。调试模式不是“更准确”开关，而是用于建立可解释的实验对照。

![按需展开的检索调试参数](screenshots/15-question-first-debug.png)

### 7. 将负反馈变成评测草稿

对回答点踩后，可以选择 `retrieval_miss`、`wrong_citation`、`unsupported_claim` 等失败类型，并填写期望答案。后端会保存历史快照，并生成 eval draft。人工审核后再把稳定、脱敏、具有代表性的样本加入固定黄金集。

| 带引用回答和安全拒答 | ✓ | ✓ |

## 状态设计

产品不能只设计成功路径。当前界面明确覆盖：

- 首次无文档的 empty state；
- 上传、URL 导入、提问和删除的独立 loading state；
- 运行中取消与 disabled state；
- 超时、限流、网络中断和服务错误；
- 同一操作的 retry，而不是要求重新输入；
- 超长标题、长答案、长 URL 与窄屏换行；
- 无引用拒答与零结果检索；
- 390px 宽度下无水平溢出。

![390px 简洁问答页与底部快捷导航](screenshots/14-evidence-ledger-mobile.png)

## 键盘与辅助功能

- 使用语义化表单、按钮、状态区域和标题层级。
- 所有主要操作可以键盘到达，焦点样式不会被重置。
- `⌘/Ctrl + K` 或非输入状态下的 `/` 聚焦问题；抽屉使用焦点闭环，`Esc` 关闭后返回触发按钮。
- 错误和加载状态不只依靠颜色表达。
- 颜色 token 同时服务亮色背景、深色 Trace 与高对比焦点。
- 在 `prefers-reduced-motion: reduce` 下关闭非必要动画和滚动效果。

## 推荐演示路径

1. 执行 `npm run demo:bootstrap` 导入五份脱敏资料。
2. 在简洁模式问“默认演示是否需要 API Key？”，展开引用。
3. 切换调试模式，观察 BM25 与向量候选。
4. 提问资料中不存在的支付或人事问题，展示拒答。
5. 点踩一条模拟回答，生成评测草稿。
6. 执行 `npm run eval:retrieval`，展示阈值和可读报告。

更详细的话术和恢复分支见[演示脚本](demo-script.md)。
