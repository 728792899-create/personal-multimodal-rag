# 端到端案例：从资料到可回归证据

本案例使用仓库自带的脱敏资料和 `mock + memory + template` 模型提供方，完整走过入库、提问、检索、引用、拒答、反馈和评测草稿。它是可复现演示脚本，不依赖真实 API 密钥或外部模型。

## 场景

团队希望确认“默认演示是否需要真实 API 密钥”，同时需要知道答案来自哪份资料、检索经过哪些阶段、错误发生后是否能安全恢复。

准备环境：

```bash
docker compose up --build --wait -d
npm run demo:bootstrap
```

`demo:bootstrap` 导入 `samples/demo-documents/` 中的五份固定资料，覆盖系统、技术、工作流、部署和评测。页面顶部会显示当前模型提供方；默认应为 `mock / memory / template`。

## 1. 入库：文件与 URL 是两条独立受控路径

![上传入口、URL 表单和已索引资料同时显示](screenshots/04-ingestion-url.png)

文件上传会检查扩展名、大小、空内容和 PDF/图片文件签名；成功解析后计算 SHA-256 内容哈希，重复资料复用已有文档。URL 导入会检查协议、凭据、DNS、重定向、最终地址、类型、大小和超时，防止最直接的 SSRF 绕过。

案例截图只展示本地脱敏资料。真实私有 URL、令牌和用户文件不应进入截图或固定样例。

## 2. 提问：先定位证据，再生成回答

在问题框输入：

```text
默认演示是否需要真实 API 密钥？
```

普通模式只保留问题、文档范围与提交动作；专家模式还可调整检索模式、检索配置、返回条数、候选条数、向量权重、MMR λ 和最低分数。

后端的处理顺序是：规范化/可选改写 → BM25 与向量召回 → 加权融合与去重 → MMR → 可选重排 → 证据门 → 回答或拒答 → 引用审计。完整因果链见[检索与可信回答](retrieval-explained.md)。

## 3. 引用：查看相邻上下文，而不只相信摘要片段

![引用详情展开来源片段与相邻上下文](screenshots/05-citation-context.png)

每条引用都保留真实分块 ID、文档名、片段、页码/标题路径和分数。点击引用后，前端调用 `/api/chunks/{chunk_id}/context`，按同一文档中的分块顺序补充前后文。这样可以发现片段是否断章取义，也能从引用回到更完整的证据范围。

引用审计会计算覆盖率和依据度，并标出无支撑主张。规则审计是可解释的第一层防线，不等同于语义事实核验；生产场景仍应按风险加入人工复核或独立判断器。

## 4. 检索追踪：把“回答不对”拆成可定位阶段

![质量面板展示检索阶段、引用审计与系统指标](screenshots/06-quality-dashboard.png)

专家视图按阶段展示候选数量、耗时、分数、回退、拒答理由和引用覆盖。定位顺序建议固定为：

1. BM25/向量分支是否召回目标分块；
2. 融合去重是否丢失候选；
3. MMR 是否因多样性压低关键证据；
4. 重排是否改变正确次序；
5. 证据门是否错误拒答或放行；
6. 最终引用是否覆盖答案主张。

## 5. 无证据拒答：答案缺口也是产品输出

输入固定负样本，例如“火星办公室的停车政策是什么？”。资料库没有相关证据时，系统返回拒答原因、资料缺口和修复建议，并保留检索追踪；它不会把低相似候选包装成事实。

黄金集中的 6 条拒答案例专门保护这条行为。拒答准确率与 Recall 同时设门槛，防止通过一味降低证据阈值换取表面召回提升。

## 6. 反馈：把一次失败变成评测输入

![负反馈、失败类型与自动生成的评测草稿](screenshots/07-feedback-eval-draft.png)

对回答点踩并选择失败类型后，后端保存历史快照和评测草稿。草稿不会自动进入黄金集：维护者仍需核对隐私、来源、期望关键词和问题稳定性，再手工加入 `eval/cases.jsonl`。这是“反馈可行动”与“评测不被噪声污染”之间的边界。

## 7. 错误恢复：保留最后一次成功状态

![API 504 错误包含重试入口，最后一次成功回答仍保留](screenshots/08-error-retry.png)

请求超时或上游不可用时，前端展示可读错误、请求 ID 和重试入口；冲突操作禁用，但最后一次成功的回答不会被空白错误页覆盖。取消使用中止语义，不被误报为业务失败。恢复服务后，重试使用同一操作快照重新提交。

## 可审查结果

这个案例同时证明四层能力：界面能完成任务、检索过程可解释、无证据能拒答、失败能进入评测闭环。它仍不证明开放域质量或多租户生产能力；完整限制见[已知边界](known-limitations.md)，固定集结果见[评测结果](evaluation-results.md)。
