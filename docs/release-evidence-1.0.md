# 1.0 发布证据与阻断项

当前候选版本是 `1.0.0-rc.1`，目标版本是 `1.0.0`。公开仓库**没有宣称生产就绪，也没有发布 1.0.0**。`GET /api/system/readiness-report` 读取部署方私有的 `RELEASE_EVIDENCE_PATH`；文件缺失、字段缺失或任一门未通过时，状态固定为 `blocked`。

> 本页把“代码/契约已实现”和“真实环境已验收”分开。固定样例、`--contract-only`、模型能力探针，以及旧版 768 维/本地模型现场记录，都不能替代 Retrieval v2 的 OpenAI 1536 维真实证据。

## RC 已提供的代码与契约

- 单工作区本地成员账号：唯一用户名、Argon2id、临时密码强制修改、`admin/editor/viewer`、会话即时撤销和最后管理员保护。
- 生产模型边界：OpenAI `text-embedding-3-large` / 1536 维；DeepSeek 回答、低置信规划和选择性重排；生产禁止本地模型和模板回答回退。
- Retrieval v2：版本化 `rag_chunks_v2_*`、持久 BM25 postings、过滤下推、HNSW/精确搜索切换、weighted RRF、Graph-lite、五路自动规划、选择性 Top-16 重排、父上下文与引用门。
- 影子索引控制面：candidate、durable rebuild、validation、promote、事务 activate 和 rollback；每个请求固定索引版本。
- 私有评测数据分布契约和校验器：200 条标注、60/140 分割、40 条双审、至少 100 条冻结后盲测。
- CI 用固定、脱敏数据执行回归和安全契约；生产 readiness 缺少私有证据时失败关闭。

这些内容证明实现路径存在，不证明目标团队、目标语料和目标规模已经通过验收。

## 质量发布门

| 指标 | 最低要求 |
| --- | ---: |
| 证据 Recall@5 | ≥ 0.90 |
| MRR@10 | ≥ 0.78 |
| 多跳完整证据链@10 | ≥ 0.80 |
| 表格 / 图片 / 公式 Recall@10 | 各 ≥ 0.85 |
| 引用正确率 / 事实覆盖率 | 各 ≥ 0.90 |
| 虚构或失效引用 | 0 |
| 拒答 F1 | ≥ 0.88 |
| 可回答问题误拒答率 | ≤ 8% |
| HNSW Recall@50 对比精确搜索 | 总体 ≥ 0.98、主要分层 ≥ 0.95 |
| 100 条真实盲测接受率 | ≥ 85% |

困难查询至少一个核心指标必须比旧版提高 5 个百分点，其他总体指标下降不得超过 1 个百分点。DeepSeek 重排在触发子集必须使 MRR 提升至少 3 个百分点且触发率不超过 50%；否则实现保留但生产默认关闭。

当前 schema v2 readiness 报告会失败关闭地检查证据身份、人工标注、质量、HNSW 分层、旧版对照、重排收益、50k/5 并发性能、查询成本、RBAC、供应商故障、恢复/回滚、14 天 soak 和安全事故。嵌入费用 15% 偏差由影子索引 validation 记录；分阶段灰度等未进入 endpoint 的运行门仍需附加签名报告，不能被视为自动通过。RC 响应中的 `production_ready_claim` 始终为 `false`，全部门通过只表示可以进入人工发布决策。

## 性能、成本和运行门

- 50k 分块、5 并发：HNSW p95 ≤200 ms；普通完整检索 ≤2 s；含规划/重排的复杂检索 ≤6 s。
- 简单/复杂问题首字节分别 ≤6 s / 10 s。
- 自动路由平均查询成本不超过关闭规划和重排基线的 1.35 倍。
- 全量实际嵌入费用相对 10% 预演投影的偏差不得超过 15%。
- 14 天至少 500 次代表性查询，可用率 ≥99.5%，无数据丢失、权限绕过、密钥泄漏或未解决 Sev-1。
- 权限绕过、索引污染、数据丢失、虚构引用，或 10 分钟内 5xx 超过 5%，必须回退完整的“索引 + 嵌入配置 + 路由 + 重排”版本；RTO ≤10 分钟、源数据 RPO=0。

## 私有证据校验

真实业务内容保存在仓库外。默认文件约定：

- `data/validation/v1-annotations.jsonl`：200 条人工标注；
- `data/validation/v1-blind.jsonl`：配置冻结后的至少 100 条真实盲测；
- `RELEASE_EVIDENCE_PATH`：readiness 使用的汇总清单。

运行数据集校验：

```bash
python3 scripts/validate_v1_dataset.py \
  --annotations /secure/evidence/v1-annotations.jsonl \
  --blind /secure/evidence/v1-blind.jsonl
```

运行发布证据校验：

```bash
export RAG_REAL_BENCHMARK_MANIFEST=/secure/evidence/release-evidence.json
export RELEASE_EVIDENCE_PATH="$RAG_REAL_BENCHMARK_MANIFEST"
npm run benchmark:real
curl --fail http://127.0.0.1:5173/api/system/readiness-report
```

`python3 scripts/validate_v1_dataset.py --contract-only` 只验证校验器和数量分布本身；它生成的是合成 contract rows，不能计入一条真实标注、双审或盲测。

## 历史证据的边界

2026-07 的 `0.4.0-rc.1` 现场记录包括 21 组许可证来源、200 份非固定样例文档、5,159 个 768 维向量、PostgreSQL/MinIO 恢复和五类故障注入。它们继续作为不可篡改的历史记录保留在[生产现场验收](production-validation.md)与[验证基线](validation-baseline.md)，但不能证明：

- OpenAI `text-embedding-3-large` 1536 维全量重建成功；
- Retrieval v2 HNSW 与持久 BM25 达到质量/延迟门；
- DeepSeek 自动规划和选择性重排有净收益；
- 新 RBAC 在真实团队中没有权限绕过；
- v1 RC 完成灰度和 14 天 soak。

不要改写历史基线以制造新版绿色结果；新证据应使用新的索引 ID、配置快照、时间戳和签名报告追加保存。

## 发布步骤

1. 完成 200 条真实标注、双审和数据集校验，冻结 60 条调优集与 140 条回归集。
2. 执行 10% OpenAI 费用预演；确认后幂等重建并验证影子索引。
3. 冻结检索配置，运行至少 100 条未参与调优的真实盲测；系统有修改时把失败样本纳入回归并补 50 条新盲测。
4. 暂停语料写入、补齐增量、保存同云模型稳定快照并事务切换；完成回滚演练。
5. 按 1–2 人、3–4 人、全员灰度，完成 14 天/500 查询 soak。
6. 关闭所有安全、数据丢失和 Sev-1 阻断；归档质量、性能、费用、灰度和恢复报告。
7. 只有全部发布门同时通过，才创建 `v1.0.0` 标签。

详细架构和切换命令见 [v1.0 升级手册](rag-v1-upgrade.md)。
