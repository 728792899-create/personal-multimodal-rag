# 面试演示脚本

## 演示目标

用 6-8 分钟证明这个项目不是普通 RAG Demo，而是一个能导入资料、检索证据、审计引用、沉淀反馈、运行评测的个人知识库工作台。

## 演示前准备

启动服务：

```bash
npm run dev
```

导入作品集演示资料：

```bash
python3 scripts/bootstrap_portfolio_demo.py
```

打开工作台：

```text
http://127.0.0.1:5173
```

## 推荐演示问题

1. `这个 RAG 项目最适合写进简历的技术亮点是什么？`
2. `如果面试官追问引用可信度，这个系统怎么降低幻觉？`
3. `这份资料有没有提到 Kubernetes 部署？`
4. `把这个项目经历改写成 3 条简历 bullet`
5. `杭州 AIGC 应用开发岗位更看重哪些能力？`

## 6 分钟演示流程

### 1. 项目定位，30 秒

说法：

> 这个项目不是做一个聊天框，而是做一个可解释、可评测、可复盘的个人 RAG 知识库工作台。核心目标是解决普通 RAG Demo 检索不可控、引用不可信和失败无法沉淀的问题。

### 2. 导入资料，60 秒

展示左侧：

- 文件上传
- URL 导入
- 文档质量分
- chunk 数
- 文档详情中的质量评分、摘要、索引生命周期

重点说：

> 我把资料导入看成一个索引任务，而不是简单保存文件。每份文档都有解析、chunk、embedding、写入向量库的状态和质量评分。

### 3. 问答与引用，90 秒

提问：

```text
这个 RAG 项目最适合写进简历的技术亮点是什么？
```

展示：

- 回答
- 引用证据
- confidence
- Trust 面板
- 引用覆盖率
- 点击证据查看上下文

重点说：

> 我不只展示答案，还展示答案为什么可信。每条引用都能回到 chunk 和上下文，答案还会做引用审计。

### 4. 专家模式 Trace，90 秒

切到专家模式，展示：

- query intent
- BM25 / Vector / Rerank 分数
- candidate_k
- MMR
- document boost
- retrieval_ms / generation_ms
- 策略对比

重点说：

> 如果回答不好，我可以判断问题出在 query、召回、排序、阈值还是生成，而不是只能猜 prompt。

### 5. 失败与缺口分析，60 秒

提问：

```text
这份资料有没有提到 Kubernetes 部署？
```

展示：

- 无证据或弱证据
- diagnostics
- 资料缺口建议
- no-answer gate

重点说：

> 好的 RAG 系统不应该硬答不知道的问题。证据不足时应该拒答，并告诉用户缺什么资料。

### 6. 反馈评测闭环，60 秒

点击：

- 不准确
- 生成评测草稿
- 专家模式运行评测草稿

重点说：

> 用户反馈不是只记日志，而是进入评测集。后续可以对比不同检索策略，形成优化飞轮。

### 7. 知识产物，40 秒

点击：

- 面试回答
- 简历 Bullet
- 存为知识卡片

重点说：

> 这个系统最终不是只回答问题，而是帮助我把个人资料转成可复用的知识产物。

## 演示结尾

可以这样收尾：

> 这个项目我最想体现的不是“我会调模型 API”，而是我理解一个 RAG 应用从资料导入、索引构建、检索排序、引用可信度、失败兜底、用户反馈到评测优化的完整工程链路。
