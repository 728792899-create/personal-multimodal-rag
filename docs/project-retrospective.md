# 项目复盘

## 为什么做这个项目

最初目标是做一个个人知识库问答系统，但普通 RAG Demo 很容易停留在“上传文档 -> 向量检索 -> 调模型回答”。这种项目面试时不够有说服力，因为它无法回答三个关键问题：

- 答案为什么可信？
- 搜不到时怎么定位问题？
- 用户反馈如何变成下一轮优化？

所以项目方向从“问答功能”调整为“可解释、可评测、可复盘的 RAG 工作台”。

## 已完成的关键迭代

### 第一阶段：基础 RAG 链路

- 文档上传与解析
- chunk 切分
- BM25 检索
- mock embedding 向量检索
- 引用回答

### 第二阶段：真实工程可用性

- Chroma / pgvector 抽象
- OpenAI-compatible embedding provider
- Query Rewrite
- MMR
- Rerank
- No-answer Gate
- 文档去重与重建索引

### 第三阶段：可信度与反馈闭环

- 文档质量评分
- 答案可信度分级
- 引用覆盖率
- unsupported claims
- 用户反馈生成 eval draft
- 操作日志与系统指标

### 第四阶段：作品化与演示

- 普通模式 / 专家模式
- URL 导入
- Parent-Child 上下文
- 答案改写
- 知识卡片
- 评测工作台
- 演示资料和面试讲述文档

## 当前项目的亮点

- 前端不是单页聊天框，而是一个三栏知识库工作台。
- 后端不是直接调用模型，而是拆成解析、检索、重排、生成、审计、评测模块。
- 每次问答都有 trace，可以定位检索和生成问题。
- 用户负反馈可以进入评测集，形成优化飞轮。
- 能用同一个项目同时展示 AIGC 应用、Vue 前端和工程产品思维。

## 当前项目的不足

- 图片 OCR/VLM 还不是强能力，不能夸大成完整多模态理解。
- 文档索引仍是同步任务，大文件体验还可以继续优化。
- Citation audit 目前偏规则检查，语义级引用验证还可以接 NLI 或 LLM-as-judge。
- 前端评测工作台已有雏形，但还可以增加指标图表和策略 A/B 对比。
- 项目更适合个人知识库规模，暂不适合作为企业级权限/多租户系统包装。

## 如果继续做

优先级建议：

1. 异步索引任务队列：上传后显示进度、失败原因、重试按钮。
2. PDF 原页跳转和高亮：增强引用可信度。
3. LLM-as-judge citation verification：判断引用是否真正支持答案。
4. 评测报表图表化：Recall@K、MRR、Citation Precision、No-answer Accuracy。
5. 文件夹监听和 GitHub 仓库导入：增强真实资料接入能力。

## 面试复盘结论

这个项目最适合作为主打项目，因为它能体现：

- 我理解 RAG 不只是模型调用，而是一条完整工程链路。
- 我能从用户体验角度做工作台，而不是只做接口。
- 我能从算法工程角度设计检索、重排、拒答和评测。
- 我能把项目做成可演示、可解释、可复盘的作品。
