# 项目复盘

## 背景

普通 RAG Demo 很容易停留在“上传文档、向量检索、调用模型回答”。这类实现能展示基础链路，但不容易定位错误发生在哪里：是文档解析失败、chunk 切分不合理、召回不准、排序错误，还是答案生成阶段产生了无证据推断。

本项目把 RAG 链路拆成多个可观察模块，并在前端展示引用、分数、trace、fallback 和可信度审计，方便调试和持续改进。

## 关键取舍

- 默认使用 hash/mock embedding，让项目在无 Key 环境下也能跑通。
- 把 Chroma、pgvector、真实 embedding 和 reranker 做成可选增强，避免默认启动过重。
- 保留专家模式，用于查看检索参数和策略对比。
- 保留普通模式，让常规问答路径不被工程参数干扰。

## Beta 加固结果

- 前端从单体页面拆成页面、组件、composable 与领域 API，同时保持原有功能路径。
- 后端路由按 documents/retrieval/quality 拆分，并补请求 ID、可选认证、限流与日志脱敏。
- Trace 改为七阶段视图，让召回、融合、MMR、排序、拒答和引用覆盖可以逐项解释。
- 固定黄金集覆盖 5 份来源、24 条可回答和 6 条拒答样本，阈值进入 CI。
- Docker 使用生产 Nginx 与健康检查；memory 索引在进程重启后从 registry 自动恢复。
- Browser 实测发现并修复了重启后只恢复文档 metadata、未恢复 chunk 的问题。

## 后续方向

- 用真实业务语料扩充困难负样本与跨文档组合问题。
- 实施 workspace schema、OIDC 网关和服务端授权，而不是把 workspace 当客户端参数。
- 在相同黄金集上对比真实 embedding、cross-encoder 与成本/延迟。
- 把 0.2 单实例 SQLite 索引任务迁移到外部队列，并接入对象存储、病毒扫描与 DLQ。
- 增强表格、版面和图片语义理解，并引入人工/NLI 引用校验集。
